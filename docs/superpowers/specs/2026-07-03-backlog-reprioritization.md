# 백로그 재우선순위 확정 (2026-07-03)

## 배경

환경 세팅(문서 정리, 작업 방식 확정) 1차 완료 후, 이전에 구두로 정리했던 6개 항목 백로그를 아래 두 기준으로 재확인했다.

**판단 기준**
1. 카페 사장님(최종 유저)에게 가장 유용한 기능 우선
2. 1-2일 이내 구현 가능한 작업 우선

**추가 고려**: 페어 레포 `Rebot-App-Customer-facing-page`(고객용 스탬프 앱)가 수집하는 DB를 이 대시보드가 그대로 보여주므로, 그 레포의 실제 데이터 쓰기 동작을 확인한 뒤 반영했다.

## 페어 레포 조사에서 확인된 사실

- `visit_logs.source`는 고객 앱에서 항상 `'kiosk'`로 하드코딩된다 (`stamp-handlers.ts:159`). `'manual'` 소스는 오직 대시보드 쪽 수동 등록에서만 발생 — 항목 4(구 6번, 방문 등록 메뉴/날짜 확장)는 대시보드 단독 작업으로 확정.
- 고객명은 선택 입력이라 자주 null이며, 재방문 시 비워두면 기존 이름이 유지된다 — AI 메시지가 이미 "null이면 '고객'"으로 처리하므로 추가 대응 불필요.
- 마케팅 동의는 최초 가입 시 1회만 저장되고 이후 갱신 로직이 없다 — 이번 백로그 범위 밖의 별도 이슈로 기록만 해둔다(미착수).
- 인증 없는 디버그 백도어 `/api/test/reset`가 고객 앱 프로덕션 코드에 남아있다 — 대시보드 레포 범위 밖이라 이번 스코프에서는 다루지 않음(별도 확인 필요 사항으로만 기록).
- 대시보드가 표시할 모든 실 데이터는 고객 앱의 QR 스캔 경로로만 생성되며, 스탬프 적립 시 `last_visit_at=now()`로 기록된다 — 신규 고객은 항상 `safe` 단계로만 잡힌다는 기존 판단이 재확인됨 (이탈 데이터 시딩이 여전히 필요).

## 쿠폰 달성 임박 타겟팅 — 신규 항목 (2026-07-03 추가)

AI 메시지 고도화(항목 2) 작업 리뷰 중 사용자가 제안한 추가 기능. 사장님이 설정한 임계값(예: 스탬프 70%, 80%) 이상 채운 고객을 별도로 조회해 "조금만 더 방문하면 리워드 완성"이라는 방문 유도 메시지를 발송하는 기능.

**항목 2(AI 메시지 고도화)에 포함하지 않고 별도 항목으로 분리한 이유**:
- 트리거 축이 다름: 기존은 이탈 위험(오래 안 옴 → 재방문 유도) 축, 이건 완주 임박(스탬프 거의 참 → 완주 유도) 축 — 타겟팅 조회 로직 자체가 다르다.
- 신규 설정값 필요: "사장님이 세팅한 수치"가 요구사항이라 `stores` 테이블에 임계값 컬럼과 설정 페이지 UI 추가가 필요하다 — 프롬프트 수정과는 별개 작업.
- 별도 UI 표면 필요: 대시보드에 "쿠폰 달성 임박 고객" 목록/필터 화면이 새로 필요해 보인다 — 기존 이탈 단계 필터와 다른 화면 요소.

## 사용자 확정 사항

- 사용자 지시 원문: "1,2,3,5 실행 후 4번 재검토하자" — 여기서 1,2,3,5는 재정렬 제안 당시의 표(이탈데이터시딩=1, AI메시지=2, 메모필드=3, KPI=4, 방문등록확장=5) 번호를 가리킨다. 즉 KPI(당시 4번)를 제외한 나머지 4개를 먼저 끝내고 KPI는 그 뒤에 범위를 다시 정하라는 뜻이며, 위 "확정된 순서"의 1~4번이 그 4개다.
- 재정렬 여부: 원래 구두로 지시했던 순서(…→KPI→메모필드→…) 대신, 이번에 제안한 재정렬 순서(이탈데이터시딩→AI메시지→메모필드→방문등록확장→KPI)를 그대로 채택하기로 확정.
