# 🚀 Rebot(리봇) 아키텍처 및 배포 가이드 (프로젝트 관리용)

본 문서는 리봇(Rebot) 프로젝트의 상업화 및 향후 확장을 고려한 **보안, 배포, 그리고 레포지토리 관리 정책**을 정리한 문서입니다.

---

## 🔒 1. 레포지토리 보안 정책 (Private 권장)

상업성을 띤 프로젝트의 소스 코드는 핵심 자산이므로 깃허브 레포지토리를 **Private(비공개)**으로 설정하는 것이 원칙입니다.

*   **지식재산권 보호**: AI 재방문 메시지 생성 프롬프트, 이탈 고객 예측 알고리즘, 크롤링 로직 등의 무단 복제를 방지합니다.
*   **요금 폭탄(해킹) 방지**: 깃허브를 24시간 스캔하는 해커 봇들로부터 실수로 유출될 수 있는 API 키(`.env`)를 1차적으로 방어합니다. (물론 `.gitignore` 세팅으로 2차 방어도 완료된 상태입니다.)
*   **테스트 영향 없음**: 코드가 비공개될 뿐, 이미 배포된 웹사이트 주소(Vercel URL 등)는 전 세계 누구나 계속 접속하고 테스트할 수 있습니다.

---

## 🌐 2. 프론트엔드 배포 플랫폼 정책 (Private 기준)

깃허브를 Private으로 닫아도, 최신 클라우드 배포 플랫폼들은 깃허브 계정 연동을 통해 무료로 배포를 지원합니다.

### Vercel (React/Next.js 정식 서비스 배포용)
*   **지원 여부**: ⭕ **무료 지원 (무제한)**
*   **설명**: 우리는 리봇 서비스 배포에 Vercel을 메인으로 사용합니다. 향후 UI를 Next.js로 고도화할 때 사용할 업계 1위 플랫폼입니다. 무료 요금제(Hobby)에서도 Private 레포지토리 배포를 제한 없이 완벽하게 지원합니다.
*   *(참고: 깃허브에서 자체 제공하는 GitHub Pages는 Private 배포 시 유료 결제가 필요하므로 우리 프로젝트에서는 사용하지 않습니다.)*

---

## 🏛️ 3. 레포지토리 구조 및 진화 방향 (Monorepo)

나중에 서비스가 커지더라도 프론트와 백엔드 레포지토리를 여러 개 파지 않고, **현재의 `rebot` 레포지토리의 이름을 그대로 유지하면서 안에서 폴더만 쪼개는 "모노레포(Monorepo)" 방식**을 채택합니다.

### 미래의 폴더 구조
```text
rebot/ (현재 레포지토리 - Private 유지)
  ├── frontend/   ← (현재) Vercel이 이곳을 바라보고 배포함. 사장님 대시보드 및 QR 스탬프 웹뷰 코드.
  ├── backend/    ← (미래) 현재 작성 중인 AI 메시지 발송 API 엔진이 이동할 폴더.
  └── README.md
```

### 브랜치(환경) 분리 전략
*   🌳 **`main` 브랜치 (Production)**: 진짜 사장님과 고객들이 쓰는 라이브 서비스 버전. 함부로 수정 불가.
*   🌱 **`develop` 브랜치 (Staging)**: 팀원들이 새 기능을 개발하고 자유롭게 테스트하는 버전. 

### 🤝 팀원 신뢰 기반 브랜치 보호 전략
시스템으로 통제하는 대신, 팀원 상호 간의 완벽한 신뢰를 바탕으로 다음 3가지 원칙을 자발적으로 엄수합니다.
1. **무조건 PR(서류)로만 합치기**: 다이렉트 푸시(Direct Push)는 절대로 하지 않는다는 팀 약속
2. **`develop`은 서로 리뷰하며 머지(Merge)**: 철저하게 목적 중심(feature, fix 등)으로 방을 파서 수평적 코드 리뷰 진행
3. **`main` 방은 신중하게 접근**: 라이브 서비스 장애 방지를 위해 1차 검증된 코드만 병합 허용
